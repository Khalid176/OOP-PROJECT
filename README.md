# Image Filter Studio
### CS1004 — Object Oriented Programming | FAST-NUCES

A fully console-based image processing application written in C++. Loads real JPG and PNG images, applies a customizable pipeline of 10 filters, and saves the result back to disk. Built as a semester project to demonstrate core OOP concepts including inheritance, polymorphism, operator overloading, friend classes, and dynamic memory management.

---

## Features

### Two User Roles

**Admin** (hardcoded credentials)
- Toggle any filter on or off — changes persist across restarts via `Catalog.txt`
- Search customers by name or CNIC
- Toggle customer block status
- View all blocked customers
- Delete a customer account (removes from both `Customers.txt` and `Sessions.txt`)
- View all sessions or sessions for a specific customer

**Customer** (registered accounts)
- Load a real JPG or PNG image from disk, or generate a built-in 100×100 checkerboard test pattern
- Browse the filter catalog (ID and name only — availability status is hidden from customers)
- Build a filter pipeline by adding multiple filters in sequence
- Apply the pipeline with an ASCII preview offered after each individual filter
- Save the result with either an autogenerated name (`CNIC_timestamp`) or a custom name
- View personal session history with a session count shown on the menu

### 10 Filters
| ID | Filter | What it does |
|----|--------|-------------|
| 01 | GrayScale | Sets R=G=B=(R+G+B)/3 |
| 02 | Invert | Sets each channel to 255 minus itself |
| 03 | Brightness Adjust | Adds a user-specified value (−255 to +255) to every channel |
| 04 | Contrast Stretch | Normalises each pixel's channels relative to its own min/max |
| 05 | Red Channel Only | Zeroes Green and Blue channels |
| 06 | Green Channel Only | Zeroes Red and Blue channels |
| 07 | Blue Channel Only | Zeroes Red and Green channels |
| 08 | Box Blur | 3×3 neighbourhood average using a deep copy to avoid bleed |
| 09 | Flip Horizontal | Mirrors the image left to right |
| 10 | Flip Vertical | Mirrors the image top to bottom |

### ASCII Preview
Two modes available after every filter application and after image load:
- **Full** — every pixel rendered as a character
- **Scaled down** — sampled at `height/20` and `width/40` steps to fit the terminal

Character mapping (darkest to brightest): `space  .  :  -  =  +  *  #  @`

## OOP Concepts Demonstrated

| Concept | Where |
|---------|-------|
| Abstract classes | `Filter`, `user`, `saveable`, `displayable` |
| Pure virtual functions | `Filter::apply()`, `user::login()`, `saveable::save()`, `displayable::display_Ascii()` |
| Multiple inheritance | `Image` inherits both `saveable` and `displayable` |
| Runtime polymorphism | `vector<Filter*>` in `FilterSession` — 10 different filter types called through base pointer |
| Operator overloading | `Pixel::operator+`, `Pixel::operator<<`, `Image::operator=` |
| Friend classes | `FilterSession` is a friend of `Image`; `F_M_Customers` is a friend of `user` |
| Rule of Three | `Image` has copy constructor, assignment operator, and destructor — all manually implemented |
| Static method | `Pixel::clamp_unity()` |
| Method chaining | `FilterSession::add_filter()` returns `FilterSession&` |
| Pass by reference | `bool& is_done` in `add_filter()`, `bool& bloocked` in `login()` |
| Dynamic memory | `Pixel**` 2D grid allocated with `new`, freed in destructor |
| Exception handling | `try/catch` at 8 points — catalog load, login, image read/write, session append, delete, toggle |
| Functions defined outside class | `Image::save()`, `Customer::login()` |
| Forward declarations | Used throughout for circular dependencies |

## File Structure

```
project.cpp          — entire source (single file)
stb_image.h          — image loading library (header only)
stb_image_write.h    — image writing library (header only)
Customers.txt        — registered customer data
Sessions.txt         — session history
Catalog.txt          — filter availability state
```

## Design Choices Beyond the Requirements

- **Blocked account login handling** — a blocked user does not burn one of the 3 login attempts. The `bool& bloocked` reference parameter signals the failure reason so the counter only increments for wrong credentials.
- **Mr./Mrs. prefix on welcome message** — gender is normalised to lowercase and used to select the correct title on the customer menu.
- **Temp file cleanup** — `remove()` is called after every delete/toggle operation so no leftover `Temp.txt`, `Temp2.txt`, `Temp3.txt` files accumulate on disk.
- **Empty state messages** — yellow warnings appear when session lists, customer lists, or blocked customer lists are empty instead of showing a blank screen.
- **Pipeline string built at add time** — the filter name string recorded in sessions is assembled as filters are added, not after they are applied, so the record is accurate even if a filter becomes blocked between add and apply.
- **Two ASCII display modes** — full resolution and dynamically scaled, with step sizes calculated from image dimensions at runtime.
